# The Meeple Planner

**Stack:** React 19 + TypeScript + Firebase/Firestore
**Purpose:** Collaborative event scheduling for board game groups and recurring hangouts

## Source vs. Build

| Location | Role |
|----------|------|
| `src/` (repo root) | **Source code — all edits go here** |
| `planner/` (this directory) | **Build output — never edit directly** |

The `planner/` directory is generated by `npm run build`. Editing files here will be overwritten on the next build.

## Dev & Build Commands

```bash
npm start          # Dev server → localhost:3000
npm run build      # Build → build/ directory, then copy to planner/
npm run deploy     # Deploy via gh-pages; use [skip ci] in commit to avoid double-build
```

Requires `.env.local` for local dev (Firebase App Check debug token).

## Critical Files

| File | Notes |
|------|-------|
| `src/App.tsx` | Root component; view routing (list / detail / create); Firebase listeners |
| `src/types.ts` | All TypeScript interfaces: Event, TimeSlot, AvailabilityResponse |
| `src/firebase.ts` | Firebase init + App Check (reCAPTCHA v3) |
| `src/services/firebaseService.ts` | All Firestore ops — CRUD + real-time subscriptions |
| `src/components/EventDetail.tsx` | ~1,700 lines; availability voting UI — most-edited file |
| `src/components/AvailabilityHeatmap.tsx` | Multi-preference date selector with color intensity |
| `src/constants/eventTypes.ts` | Category theming: board-game, hangout, worker-bee, dnd, other |
| `src/utils/dateUtils.ts` | `parseLocalDate()` / `formatLocalDate()` — always use these |

## Data Model

**Event**
```
title, timeSlots[], participants[], isActive, isCompleted,
rescheduleVote, reactions, links
```

**TimeSlot**
```
id, date (YYYY-MM-DD), time (HH:mm | 'all-day')
```

**AvailabilityResponse**
```
participantName, timeSlotId, preference (available | tentative | preferred | unavailable)
```

Firestore collections: `events`, `responses`

## Key Patterns

- **Real-time first:** use `onSnapshot()` listeners; always unsubscribe on component cleanup
- **Preference order:** unavailable < available < tentative < preferred
- **Date handling:** always use `parseLocalDate()` — never `new Date(dateString)` directly (timezone bugs)
- **Anonymous voting:** voter UUID stored in `localStorage` under key `meeple_voter_id`
- **EventDetail has ~20 hooks** — make surgical edits; read the surrounding context before changing anything

## Environment

- Firebase project: `the-meeple-planner`
- App Check uses reCAPTCHA v3 in production; debug token via `REACT_APP_APPCHECK_DEBUG_TOKEN` in `.env.local`
